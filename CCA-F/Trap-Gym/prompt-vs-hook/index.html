Prompt or hook?

This is the exam's most common trap. A rule that must hold every time comes with answers that make the prompt clearer. A nice-to-have comes with answers that build code. Learn to tell the two apart, and a whole family of questions becomes easy.

D1 Agentic ArchitectureExam guide 1.4 and 1.5About 15 minutes

Start here: the cashier and the till

A shop has two ways to make its cashiers behave.

Tell them. A note by the till says “offer the loyalty card”, and the manager shows them how once. Most cashiers do it most of the time. If one forgets now and then, nothing bad happens.
Build it into the till. The till won't open for a refund over $150 without a manager's key. It works every time, but someone had to build it, test it and maintain it.

Claude works the same way. A prompt (instructions, plus a few example chats) is the note by the till: followed most of the time, cheap to change. A hook is code that runs every time Claude calls a tool. It is the till that won't open.

The one question to ask: if this goes wrong once, is that acceptable?
  • Yes (a suggestion, a tone, a style): use a prompt instruction plus a few examples.
  • No, an action must not run (a refund over the limit): a PreToolUse hook that blocks the call.
  • No, data must not reach Claude (a card number): a PostToolUse hook that strips it from the result.
  • No, one step must come before another (verify identity, then refund): a prerequisite gate in code.

Words in the question that tell you which side you're on

Prompt side

  • suggest, encourage, prefer
  • tone, style, wording
  • “a retention idea, not a business rule”
  • “most appropriate”, “simplest”: they ask for the right size, not the strongest

Code side

  • must, never, every time, stop completely
  • money, refunds, identity, security, compliance
  • “a prompt already says so, yet…”
  • “guarantee”, “deterministic”

The rates are illustrative, chosen to show the shape. They are not measurements. The exam guide's point is that prompt instructions have a non-zero failure rate, while hooks are deterministic for what they can see: tool calls and tool results.

Things to try: refund + prompt, then refund + PreToolUse. Then pause + PreToolUse to see the trap in reverse. Last, card number + PreToolUse, the right family but the wrong hook.

The three traps

TrapWhat the wrong option looks likeWhy it's wrong
Prompt where code was needed“Move the rule to the top of the prompt”, “add examples”, “state it in capitals”, for a money, security or must-never rulePrompts are followed most of the time. A rule that must hold every time needs code.
Code where a prompt was enoughA hook, classifier or new subagent for a suggestion or a toneOverbuilt. More to build and maintain, and it can block real users when it misreads.
Right family, wrong hookPostToolUse to stop an action; PreToolUse to hide data; a hook that only logsPreToolUse acts on the call, before it runs. PostToolUse acts on the result, before Claude reads it. Logging prevents nothing.

Practice: three exam-style questions

Answer first, then open “Think it through”.

Rule to remember

Must hold every time → code. Nice to have → prompt and examples. Stop an action with PreToolUse; hide data with PostToolUse.

Exam guide 1.4: “When deterministic compliance is required (e.g., identity verification before financial ops), prompt instructions have a non-zero failure rate.” Exam guide 1.5: “Hooks give deterministic guarantees vs prompt-based probabilistic compliance.”
