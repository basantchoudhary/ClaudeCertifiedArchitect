Which built-in tool?

The trap: almost any tool can be made to do the job, by reading everything, by running a shell command, by retrying an edit. The exam wants the one built for the job: Grep for text inside files, Glob for file names, Edit for one unique change, and Read + Write when Edit can't find a unique match.

D2 Tool Design & MCPExam guide 2.5About 12 minutes

At a glance: use Grep to search inside files and Glob to find files by name pattern, use Edit for a small targeted change, and when Edit fails because the text appears more than once, Read the whole file and Write it back.

Start here: the cookbook

You are looking for a recipe in a thick cookbook.

Finding. You either flip to the index of dish names (that's Glob: finding by name) or scan the pages for the word “saffron” (that's Grep: finding by what is written inside).
Changing. To fix one typo you cross it out and write the right word (Edit). If the same phrase appears five times and you can't point to just one, you copy the page out fresh, with the one change (Read, then Write).

Claude Code has six built-in tools for this. Glob matches file paths against a pattern such as **/*.test.ts (** means “any folder, any depth”). Grep searches the text inside files. Read opens one whole file. Edit swaps one piece of text for another, and only works when that text appears exactly once. Write replaces a whole file. Bash runs shell commands, such as tests or builds.

The one question to ask: am I looking for a file by its name, or for text inside files, and is the change small enough for one unique match?
  • A file by name or path pattern: Glob.
  • Text inside files (callers, a header, a setting): Grep, then Read the matches.
  • A small change whose text appears once: Edit.
  • Edit failed because the text is not unique: Read the whole file, then Write it back.
  • Learning how code flows: Grep the entry points, then Read to follow imports. Not everything up front.

Words in the question that tell you which tool

Points to Grep

  • every place that calls
  • which files mention
  • find the function, search the contents
  • “file names don't say which files use it”

Points to Glob

  • all files named
  • every *.test.tsx
  • files matching a pattern
  • “every generated file follows the naming rule”

Points to Read + Write

  • Edit failed
  • the text appears more than once
  • not unique; identical blocks
  • told apart only by position

The four traps

TrapWhat the wrong option looks likeWhy it loses
OverbuiltUse Glob with a broad pattern and Read every file it returns to find the callersIt reads far more than needed. Grep finds the files that contain the name directly.
Wrong toolRun grep, find or sed through the Bash tool insteadThe built-in tools are made for content search, path search and edits. Reaching for Bash adds nothing, and sed can change every match.
Only usually worksRetry Edit with a longer piece of surrounding text until the match is uniqueIt can take several tries, and with identical blocks the text may never be unique. The guide's fallback is Read + Write.
OverbuiltRead the whole codebase up front so Claude has the full pictureIt floods the context. Find entry points with Grep and follow imports with Read.

Rule to remember

Grep searches inside files, Glob finds files by name, Edit needs a unique match, and Read + Write is the fallback when it isn't unique.

Exam guide 2.5: “Grep = content search; Glob = file path patterns; Read/Write = full file ops; Edit = targeted change via unique text match.” “When Edit fails on non-unique match → Read + Write fallback.” “Build understanding incrementally: Grep entry points → Read to follow imports/trace flows (not read-all-upfront).”
