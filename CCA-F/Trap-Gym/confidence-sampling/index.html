Confidence and sampling

An extraction pipeline scores 97% overall, and the team wants to switch off human review. The tempting answers trust that number, or a thin random sample, or Claude's own sense of how sure it is. Each can hide one document type or field that fails badly. The exam's answer is to measure by type and field with stratified random samples, and route review by calibrated field confidence.

D5 Context & ReliabilityExam guide 5.5About 12 minutes

At a glance: a high overall accuracy can hide one weak document type or field, so measure accuracy by type and field with stratified random samples before automating.

Start here: the school average

A school's average exam score is 85%, so the head says every class is doing fine.

The average. One number for the whole school. A class of 30 scoring 40% barely moves it, because hundreds of other pupils are doing well.
Class by class. Someone checks each class, and the one at 40% stands out at once. Only looking at each group showed it.

An extraction pipeline is the same. Claude reads invoices, receipts, scans and handwritten forms and pulls out fields such as the amount. Stratified random sampling means picking a random sample from each group (each document type), so a rare type gets enough documents to measure. Calibrated confidence means a confidence score per field that has been checked against a labelled set (documents where people wrote down the right answers), so “90% confident” really means right about 90% of the time. Then low-scoring fields go to a person.

The one question to ask: has accuracy been checked for each document type and field, or only as one overall number?
  • One overall number (“97% across all documents”): not enough. Measure by type and by field first.
  • A plain random sample: rare types barely appear in it. Sample each type on its own (stratified).
  • Deciding which fields people check: use field-level confidence calibrated on a labelled set, not Claude's own unchecked rating.
  • After launch: keep a stratified random sample of the confident, auto-posted fields, to measure how often they are wrong.

The four traps

TrapWhat the wrong option looks likeWhy it loses
Masks weak spots“Automate fully because overall accuracy is 97%”It works for most documents, but the average can hide a type or field that fails badly.
Too thin“Have people review a random 5% of all documents”A useful spot check, but an unstratified sample can hold almost none of the rare, weak document type.
Uncalibrated“Send only low-confidence extractions to human review”It catches some errors, but without calibration and sampling, confident errors pass straight through unseen.
Unreliable proxy“Ask Claude to rate its own confidence on every field”A signal, but self-rated confidence has to be calibrated against labelled data before it can route review.

Rule to remember

Don't trust the average: check each type and field before you automate. Sample each type on its own, and route review by field confidence calibrated on labelled data.
