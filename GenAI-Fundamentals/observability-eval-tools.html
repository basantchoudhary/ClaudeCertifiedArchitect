1 · Three concerns, one blurred market framing

Observability, evaluation and the gateway are three different questions, and almost every vendor in this space now claims all three. That is why the market looks confusing: the categories are clean, the products are not.

Concern The question it answers When it runs What it produces
Observability “Why did this particular run behave that way?” Always, in production Traces, spans, token counts, cost, latency, errors
Evaluation “Is version B better than version A — and on what evidence?” In CI before release, and sampled in production Scores against a dataset, pass/fail gates, regressions
Gateway “Who is allowed to call what, at what cost, through which route?” On every request, in the path Routing, keys, quotas, budgets, caching, logs

The loop is the point. Observability is not a dashboard you look at — it is the source of your eval data. Production traces that went wrong become dataset rows; the dataset gates the next release. A team with tracing but no path from a bad trace to a test case has bought a logging bill, not a quality process.

2 · The capability vocabulary definitions

The matrices below use these columns. Vendors use the same words for slightly different things, so pin the meaning down before comparing.

TracingA span tree for one run — every LLM call, retrieval, tool call and nested agent step, with inputs, outputs, latency and tokens.
Prompt managementPrompts stored, versioned and fetched at runtime, so changing one is a deploy-free operation with an audit trail.
DatasetsCurated input → expected-output pairs, ideally built from real production traces rather than invented.
ExperimentsRun a whole dataset through a specific prompt/model version and compare aggregate scores against a previous run.
LLM-as-judgeA model grades an output against a rubric. Cheap and scalable; needs calibrating against human labels or it silently measures nothing.
Human annotationReview queues where people label traces — the ground truth that calibrates every automated score.
Online evalScoring a sample of live production traffic, not just the test set. The only way to catch drift in real inputs.
Cost trackingTokens converted to money and attributed to a team, user, feature or customer.
Monitoring & alertsThresholds and anomaly detection on latency, cost, error rate and quality scores — with somewhere for the alert to go.
OTel in / outWhether it ingests OTLP, and whether it re-exports raw spans elsewhere. The second one is what makes the choice reversible.
Self-hostCan you run the whole thing in your own network — genuinely, not as a crippled community edition.
Agent tracesFirst-class handling of multi-step loops, tool calls, sub-agents and retries — not just a flat list of LLM calls.

5 · What “eval” actually means framing

“We need evals” is four different projects wearing one word. Tools specialise in different rows, and buying the wrong row is the most common mistake in this category.

Kind What it checks Runs where Tools built for it
Unit / assertion evals Deterministic checks on one output: JSON valid, contains the citation, under N tokens, no PII, latency budget CI, on every PR promptfoo, DeepEval, pytest + any judge library
Regression evals A curated dataset scored before and after a change — did the change make it worse anywhere? CI, pre-release gate Langfuse, Braintrust, LangSmith, Opik, MLflow Evaluate
RAG-specific evals Faithfulness, answer relevance, context precision/recall — separating retrieval failure from generation failure CI and offline analysis Ragas, Phoenix, TruLens, continuous-eval
Agent / trajectory evals Did it pick the right tools, in a sensible order, without looping — and did the task complete? CI, and sampled in production Inspect AI, DeepEval, AgentEvals, Opik, Agent Evaluation (Databricks)
Safety / red team Jailbreaks, prompt injection, toxic and unsafe output, data leakage Pre-release, and periodically garak, PyRIT, promptfoo redteam, Giskard
Benchmarks Public academic scores — MMLU, GSM8K, HumanEval. Useful for picking a model, near-useless for your app Model selection only lm-evaluation-harness, HELM, Inspect AI
Online / production eval Scoring a sample of real traffic; user feedback; drift in inputs Continuously, in production Langfuse, Galileo, Arize, Datadog, Lakehouse Monitoring
The uncomfortable truth about eval tooling. Every tool here will run graders for you. None of them will tell you what a good answer looks like in your domain — that is a dataset with human labels, and it is the expensive part. Teams routinely spend three months choosing an eval platform and then run it against forty examples someone invented on a Friday. Buy the runner, build the dataset. The dataset is the asset; the runner is replaceable in a week.

8 · Safety & red-team tooling often missed

A separate category, and the one most often discovered late — usually during a security review, three weeks before launch. These generate adversarial inputs rather than scoring your own.

Tool Origin What it does Use it for
garakApache 2.0NVIDIA A vulnerability scanner for LLMs — dozens of probe families (jailbreak, encoding attacks, prompt leakage, toxicity, package hallucination) run as a sweep “Scan this endpoint and tell me what breaks”
PyRITMITMicrosoft A risk-identification framework with multi-turn attack orchestration and converters — automates the escalating conversation, not just single prompts Structured red-team programmes; underpins Azure's red-teaming agent
promptfoo red teamMITpromptfoo Generates application-specific attacks from a description of your app, mapped to OWASP LLM Top 10 and NIST AI RMF Red teaming that produces an auditable report
DeepTeamApache 2.0Confident AI Red-teaming built on DeepEval's metric modelAlready standardised on DeepEval
Giskard scanApache 2.0Giskard Automatic probe generation across hallucination, bias, injection and disclosure A first pass with almost no setup

Red teaming finds problems; guardrails are what you build to stop them. Running a scan without a plan for fixing what it finds generates a report nobody can action — pair every red-team tool with the enforcement layer that will carry the fix.

Two asymmetries worth naming. First, Databricks and Azure ship an opinionated, integrated story; AWS and GCP give you strong components you assemble. 11 · Five stacks that actually work practice

Situation Stack Why this shape
One team, first production app OTel instrumentation → Langfuse (hosted) · promptfoo in CI · direct provider SDK, no gateway yet A gateway before the second application is premature. Everything here is a weekend of work.
Several teams, no platform mandate LiteLLM Proxy → Langfuse (self-hosted) · promptfoo + Ragas in CI · Presidio guardrails at the gateway The gateway becomes the control point the moment more than two apps exist. Cost attribution stops being a spreadsheet.
Regulated enterprise, Azure-standardised APIM AI policies → AI Foundry evaluation + Content Safety · App Insights for traces · AI Red Teaming Agent pre-release Data residency and identity integration usually decide this before anyone compares features.
Data already on Databricks Mosaic AI Gateway → MLflow Tracing → Agent Evaluation + Review App · Lakehouse Monitoring on inference tables The governance boundary is already Unity Catalog. Adding an external tool means exporting the very data you were trying to keep governed.

12 · How these tools bill you economics

The pricing model matters more than the sticker price, because LLM payloads are unusually large and the bill scales with something you do not control.

Billing model Who uses it What surprises people
Per trace / per spanLangfuse Cloud, LangSmith, Braintrust An agent run is dozens of spans, not one. Agentic workloads can cost 20–50× a simple chat app at identical user volume.
Per GB ingestedDatadog, Splunk, Elastic Prompts and responses are large text blobs. Full payload capture on a RAG app can dwarf the rest of your APM bill — sample it, or truncate.
Per evaluation runBraintrust, hosted eval platforms Plus the judge model's own token cost, which is billed by your model provider and easy to forget entirely.
Per seatHumanloop, PromptLayer, Vellum Fine while it is the AI team; re-price it before you invite the whole product org in.
Self-hosted infrastructureLangfuse OSS, Phoenix, SigNoz Free licence, real cost: Postgres + ClickHouse + object storage, plus someone to own upgrades and retention.
Bundled into the platformDatabricks, Azure, AWS, GCP “Included” usually means the compute and storage are billed elsewhere on the same invoice — cheap to start, hard to attribute later.
Set sampling and retention on day one. 100% payload capture with 90-day retention is the single most common source of a surprise observability bill. Full capture on errors and a small sample of successes gives you nearly all the debugging value at a fraction of the ingest.

13 · Decide these before you buy checklist

  1. Can it export raw OTel spans elsewhere? If not, you are choosing instrumentation and backend together, permanently.
  2. Where do payloads live? Prompts and responses routinely contain customer data. “SaaS with a DPA” and “self-hosted” are different answers to a question Legal will ask — better before the pilot than after.
  3. What is the path from a bad production trace to a test case? If it is manual copy-paste, evals will quietly stop being updated within a month.
  4. Who calibrates the judges? An LLM-as-judge that nobody has checked against human labels produces confident numbers that measure nothing.
  5. What is sampled, and what is retained for how long? Decide before the first bill, not after.
  6. Does it understand agents? Many tools show a flat list of LLM calls. If you are building loops with tools and sub-agents, a flat list is close to useless.
  7. What happens when it is down? Tracing should fail open and asynchronously. A blocking observability call in the request path is an outage waiting for a bad afternoon — and a proxy-based tool is in that path by design.
If you take one thing: instrument with OpenTelemetry, keep the backend swappable, put a cheap eval in CI on day one, and spend your real effort on the labelled dataset — the only artefact here that gets more valuable over time and cannot be bought.
