🧭 Stack Decisions

Seven layers · what actually constrains what · and why the permutation count is a red herring
The confusion this page resolves. "Claude" names two different things at two different layers — a model, and an agent framework. So does "OpenAI". Once the layers are separated, the question "does choosing X restrict me to Y?" has a short, mechanical answer.

1 · The seven layers concept

Read from the bottom up. Each layer is chosen separately — but only two edges between them are real constraints.

1LanguagePython · TypeScript · Java · .NET · Go  — decides which SDKs exist for you, and nothing else
2Runtimelaptop · container · serverless function · Databricks job  — orthogonal to every other layer
3Orchestrationnone (plain code) · agent framework · graph framework · durable execution  — the only genuinely free choice, and the one that decides lock-in
4Client SDKAnthropic SDK · OpenAI SDK · boto3/Bedrock · Vertex SDK · LiteLLM · raw HTTP  — follows from the wire format
5GatewayKong · Azure APIM · LiteLLM Proxy · Portkey · none  — pins the wire format
6Provider / hostingAnthropic API · Azure OpenAI · Bedrock · Vertex · Databricks Serving · self-hosted vLLM
7ModelClaude Sonnet · GPT-4-class · Llama · Gemini  — a config value, if layer 3 was chosen well
free — choose independently constrained — usually decided for you the decision that matters
The same word at two layers. Claude at layer 7 is a model. Claude Agent SDK at layer 3 is an agent framework. You can use the model without the framework — most systems should. You cannot use the framework with a non-Claude model. The same trap exists for OpenAI (a company, a wire format, an SDK, and an agent framework).

2 · Only two edges are real constraints key insight

Constraint A — the wire format pins the client

There are effectively two formats in the world:

  • OpenAI Chat Completions — the de-facto standard. Azure OpenAI, most gateways, most open models, most self-hosted servers.
  • Anthropic Messages — Anthropic API; also available on Bedrock and Vertex.

Your gateway speaks one of them, and that decides your client SDK. It is not a judgement call.

Constraint B — orchestration decides lock-in

The rule that resolves almost every "am I locked in?" question:

Frameworks that own the loop are tied to a model family.
Frameworks that own the graph are model-agnostic.
Plain code is always agnostic.

An agent framework decides what to call next, so it is built around one model's tool-calling and stop semantics. A graph framework only decides what runs after what and takes whatever client you hand it.

So: does the Claude Agent SDK restrict you? Yes — but only if you adopt the framework. Using Claude the model restricts nothing, and using the Anthropic client for a plain "system prompt + messages → text" call is the most portable shape a model call has. Keep the model at the edges and the provider stays a configuration choice rather than an architectural one.

4 · Why the permutation count is a red herring

Multiplied out, the stack looks terrifying:

5 languages× 4 runtimes× 6 orchestration× 6 clients× 5 gateways× 6 providers× 10 models =~216,000

But the layers cascade rather than combine. In practice you take four decisions, in this order, and each one collapses the space:

#DecisionWho really makes itWhat it collapses
1Provider + gatewayYour organisation, usually before you arriveLayers 5 and 6 — down to one
2Wire formatNobody — it falls out of #1Layer 4 — down to one
3OrchestrationYou. The only free architectural choiceDecides whether layer 7 stays free
4ModelYou — measured, not assertedA config value if #3 was chosen well

Language and runtime are orthogonal to all four. So the real decision tree is four nodes deep, not seven — and only one node is genuinely yours.

6 · Building the mind map practice

Draw it as a ladder, not a web — seven rungs bottom to top — and annotate each rung with three things:

  1. Who decides it — you, your organisation, or physics (the wire format).
  2. What it constrains — draw an arrow only where a real constraint exists. There are exactly two: gateway → client, and orchestration → model family.
  3. Reversibility — how much work to change it later. Model: a config value. Gateway: a base URL. Orchestration: a rewrite. Language: a rebuild.
The one thing to internalise: the layers people argue about — model, provider, gateway — are the cheap, reversible ones. The layer nobody argues about, orchestration, is the expensive irreversible one. Spend your design time there and treat the rest as configuration.
