The lightest protocol that fits

D3 · IntegrationGuide lines 3.7

At a glance: Pick the lightest mechanism that meets the reuse, ownership and security needs: a direct API call or CLI for one known call, an MCP server for a capability many AI clients share, and agent-to-agent when another party's agent owns the whole job.

There are several ways to connect Claude to another system. A direct API call, usually wrapped as one tool in your app, is the simplest: one application, one known call, nothing to share. An agent that already has a shell can use a familiar command-line tool (CLI) without anything new being built.

MCP (the Model Context Protocol) is a standard way to expose tools and data so that many AI clients, such as Claude Code, the desktop app and your own agents, can use the same server. It pays off when several clients need the same capability, or when the owning team wants one place to control access and change the backend without breaking every client. For a single fixed call it is extra machinery.

Agent-to-agent means handing a whole goal to someone else's agent, which runs its own multi-step process with its own private systems. It fits when the other party owns the logic and will not expose its systems. If they offer a plain, documented endpoint for what you need, calling that endpoint is lighter. The trap runs both ways: a heavy protocol for one call, or custom glue in every client for a tool many share.

Change one fact

A freight company's quoting assistant is a single internal app. To quote a shipment, Claude needs the current rate from the company's own rate service, which has a documented REST endpoint taking origin, destination and weight. The call is always the same, and no other AI client needs rates. How should rate lookup be integrated?

    Words in the stem that signal this trap

    • “only this one application needs it”
    • “several teams and AI clients need the same tool”
    • “each team is writing its own integration”
    • “the partner runs its own agent and will not expose its systems”
    • “a coding agent with a shell”
    • “a documented endpoint” for a single call
    Rule to remember: Start from the lightest mechanism and move up only when a need demands it: direct call for one known call, CLI for an agent with a shell, MCP when many AI clients share it, agent-to-agent when another party's agent owns the job.

    Practice

    Practice 13.1 · Choose one.

    An online shop's support assistant must tell customers where their parcel is. The courier offers a documented tracking endpoint that returns the status for a tracking number. It also markets a new courier agent that handles complaints and redelivery over several steps. Only the status is needed. Which integration fits best?

    1. Send each tracking question to the courier's agent over an agent-to-agent protocol.
    2. Build an MCP server around the courier's endpoints for any future AI client.
    3. Have the assistant browse the courier's public tracking page for each parcel.
    4. A tool in the support assistant that calls the tracking endpoint directly.
    Show answer

    Answer: D. The deciding fact: only the status is needed, and a documented endpoint returns it. One known call from one app is the lightest fit.

    • A ❌ Works for handing over complaints or redelivery, but a status lookup is one call, not a goal.
    • B ❌ Works when several clients need it; here there is one assistant and no reuse.
    • C ❌ Works when no endpoint exists, but page scraping breaks easily and a documented endpoint is available.
    • D ✅ A tool in the support assistant that calls the tracking endpoint directly.
    Practice 13.2 · Choose one.

    A retailer's stock system is used by three AI clients: a store-staff assistant, a buying agent and analysts in the Claude desktop app. Each queries the stock database tables directly with its own code. The stock team plans a schema change next month and does not want to coordinate with three client teams every time. Which mechanism fits?

    1. An MCP server, owned by the stock team, exposing stock lookups as tools.
    2. Keep direct database queries and send each client team the new schema early.
    3. A stock agent that the other clients ask in plain language for what they need.
    4. A command-line tool for stock lookups installed wherever the clients run.
    Show answer

    Answer: A. The deciding fact: the owning team wants to change its backend without breaking several AI clients. An MCP server it owns gives one stable interface for all of them.

    • A ✅ An MCP server, owned by the stock team, exposing stock lookups as tools.
    • B ❌ Works for one client, but every future schema change still needs three teams to update.
    • C ❌ Works when another party owns a multi-step job; here clients need simple lookups, and an agent adds delay.
    • D ❌ Works for agents with a shell, but two of these clients have none.
    Practice 13.3 · Choose one.

    A data team's nightly pipeline sends each new support ticket to Claude for a category label, then needs the label stored in the warehouse. An engineer proposes an MCP server for the warehouse so that Claude can write each label itself. No other AI client uses the warehouse. What should the architect recommend?

    1. Build the MCP server, so the write step can be reused by future AI clients.
    2. Give Claude a shell so it can run the warehouse's command-line loader itself.
    3. Have Claude return the label as structured output and let the pipeline write it.
    4. Create a warehouse agent that receives each label and decides how to store it.
    Show answer

    Answer: C. The deciding fact: a fixed pipeline makes one known call and no other AI client needs the warehouse. Claude returns the label; ordinary code does the write.

    • A ❌ Works when several AI clients share the warehouse; here none do, so it is extra machinery.
    • B ❌ Works for interactive coding agents, but it gives a batch step far more power than writing a label needs.
    • C ✅ Have Claude return the label as structured output and let the pipeline write it.
    • D ❌ Works when another party owns a multi-step job; storing a label is one fixed write.
